# Starter Kit Theme

FSE (Full Site Editing) WordPress theme, **separate VCS repo** (`github.com/solidbunch/starter-kit-theme`,
source-installed via Composer VCS repository into the foundation at
`web/wp-content/themes/starter-kit-theme/`, current local checkout on `develop`). PSR-4 autoload:
`StarterKit\` → `src/`, `StarterKitBlocks\` → `blocks/`, `StarterKitTests\` → `tests/`.

Requires `php: >=8.4` (`composer.json`) — same as the foundation. **Known doc drift:** `README.MD`
("PHP 8.1"), `phpcs.xml` (`testVersion="8.1"`), and `.github/workflows/workflow-code-qa.yml`
(`PHP_VERSION: '8.1'`) all still say 8.1. Stale, not a second real requirement — don't use 8.1-only
syntax and don't "fix" these as a side effect of unrelated work; report it if you touch that area.

## What "blocks" means here

The theme is FSE (Full Site Editing): every `templates/`/`parts/`/`patterns/` file is just
Gutenberg block markup (see `content-types.md`), and that markup is built almost entirely from
this theme's own **custom Gutenberg blocks** — `starter-kit/section`, `starter-kit/row`,
`starter-kit/column`, `starter-kit/heading`, ... — not WordPress's default block library (most
default blocks are actively disabled, see `gutenberg.php` in `architecture.md`'s config table). A
block is a self-contained unit under `blocks/<Name>/`: a `block.json` (registration metadata) +
`Block.php` (PHP side — asset registration, optional server-render callback) + `src/index.jsx`
(editor UI + how it saves into post content). Two kinds exist — **static** (content baked into
post HTML at save time, e.g. `Section`, `Heading`, `Button`) and **dynamic** (PHP renders it fresh
on every request from DB/meta data, e.g. `News`) — plus a **full-page CF-backed** variant (one
dynamic block whose entire content comes from Carbon Fields meta on the current post, letting an
admin "fill in fields" instead of composing nested blocks). All of this — the type decision,
folder shape, `Block.php` skeleton, and a set of REST-context gotchas that cause silently-empty
dynamic blocks — is in the nested `blocks/CLAUDE.md`, which loads on demand when a file under
`blocks/` is read (no `@import` needed here). Read it in full before writing any block code.

**Known stale artifact:** `blocks/PageContent/` has only a `build/` folder — no `block.json`, no
`Block.php`, no `src/`. It's leftover compiled output from an example run of a (currently deleted,
uncommitted) `/make-template-block` command with `PageContent` as the example block name — see the
theme's git history / working-tree state. `Init::loadBlocks()` skips any folder without
`block.json`, so it isn't registered and isn't a real block — don't build on it or treat it as a
template; it's safe to delete `blocks/PageContent/` if you want to clean it up, but that's a
separate decision from documenting the theme.

## Structure

```
src/                  # PHP, PSR-4 StarterKit\ — see architecture.md + conventions.md
blocks/                # Gutenberg blocks, PSR-4 StarterKitBlocks\ — see blocks/CLAUDE.md
config/                # Theme config (arrays) + DI container wiring — see architecture.md
templates/             # FSE page templates (*.html, block markup) — see content-types.md
parts/                 # FSE template parts: header.html, footer.html — see content-types.md
patterns/              # Reusable block patterns (*.php, header-comment metadata) — see content-types.md
assets/                # src/ (js, styles) compiled by Laravel Mix into build/ — see build-and-ci.md
tests/                 # PHPUnit, StarterKitTests\ — see build-and-ci.md
webfonts-loader/        # Font-to-icon-font build inputs for webpack.mix.js
```

## Hard rules

- Never edit `vendor/`, `node_modules/`, or anything under `assets/build/` / `blocks/*/build/` —
  all compiled/Composer-managed, regenerated by `composer install` / `npm run dev|prod|watch`.
- Never register a CPT, meta box, or block manually outside its designated registration point
  (`Hooks.php` for everything except blocks, which self-register — see `architecture.md` /
  `blocks/CLAUDE.md`).
- `defined('ABSPATH') || exit;` at the top of every PHP file (PSR1 side-effect exclusion is
  configured in `phpcs.xml` specifically for this line — don't remove it thinking it's dead code).
- Lint before committing: `composer lint` (PHPCS, PSR-12 + PHPCompatibilityWP) and
  `npm run lint` (Stylelint + ESLint) — see `build-and-ci.md`.
